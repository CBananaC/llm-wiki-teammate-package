UI upgrade options · 2026

A layout study for the intro website

把展示空間留給工具，
把閱讀空間留給文字。

三個不依賴外部嵌入內容的 UI 方向。每個方向都以手工製作的 review-tool mock panel 示範：工具可以被放大觀看，長篇、有層次的文字則有自己的閱讀位置。

這次升級要解決的事

  • 將 review tool 從背景中抽出，成為清晰的展示舞臺。
  • 讓標題、段落、清單和證據說明不再被浮動卡片遮住。
  • 每一個 tab 只顯示自己的內容，並保留 compact cover-style top screen。

Option 01 · Showcase first

展示優先：先看工具，再讀內容

最適合第一眼介紹平台功能。 把 review tool 放在整個畫面的第一層，長文在其下方成為完整的 editorial reading column；不需要把卡片疊在圖片或工具上。

工具是主角，文字不再是浮在上面的卡片。 這個方向把每一個內容 tab 當成一個小型展覽頁：上方先保留一個縮短版的 cover-style top screen，接著用完整寬度展示 review tool。讀者先看到平台如何工作，再向下閱讀設計理念與研究方法。

閱讀順序

  1. 看到文件標題、AI 摘要與原文引文。
  2. 向下進入結構化文字，理解為什麼需要這個工具。
  3. 在證據說明中區分 AI 候選與研究者確認。

適合的文字結構

  • 一段引導文字，說明讀者現在要看什麼。
  • 小標題分開方法、證據和研究者判斷。
  • 用 note box 補充狀態，而不是把所有訊息都放在工具面板內。

最後標示判斷

03 / VERIFY

長篇敘事最需要的是狀態清楚：哪些是 AI 候選、哪些已由研究者確認、哪些仍然需要回到原始來源。這些資訊可以用小型狀態標籤呈現。

三個方向怎麼選？

01 展示優先

推薦給：平台介紹、第一個功能展示、需要大面積呈現工具的頁面。閱讀流最自然，實作也最直觀。

02 左右分欄

推薦給：需要讓讀者同時看工具和說明的段落。適合桌面版，但要替窄螢幕準備上下堆疊。

03 研究工作臺

推薦給：方法介紹和長篇結構化內容。最能保留流程感，但需要更精準的 sticky 和 mobile 行為。

# UI ideas — 第三部分

## Purpose

Teach how the platform can be adapted to another research question and another corpus. This tab should feel like a practical workshop rather than another product tour.

## Main structure

Organise the tab as a reusable recipe:

`研究問題` → `史料準備` → `OCR` → `結構化資料` → `AI Skill` → `批次分析` → `研究者核驗` → `研究記憶／後續研究`.

Let users click any step to see its inputs, outputs, and the decisions a researcher must make.

## Suggested interactive sections

### 適合的研究問題

Offer three example question cards, such as policy formation, central–local interaction, and transmission delay. Each card previews which document fields, relationships, and visualisations would be needed. Keep the examples clearly labelled as possible research questions, not completed findings.

### OCR and material preparation

Use a before/after slider: scanned page on one side, OCR text on the other. Add small callouts for vertical text, handwriting, page structure, and uncertain characters. A warning badge can explain that OCR output still requires checking against the image.

### JSON and import

Show a document moving from image to structured fields. Use expandable fields for `文書類型`, `作者`, `日期`, `正文`, and `史料來源`. The screen should make provenance visible rather than treating JSON as an invisible technical step.

### 建立新的 AI Skill

Use a form-like card with four prompts:

- 這項 Skill 要回答哪一個研究問題？
- 要從原文提取哪些資訊？
- 必須保留哪些原文引文？
- 研究者要如何核對結果？

The result can be a sample Skill outline, but it should be presented as a draft for researcher testing.

### AI Chain and model choice

Show a small chain of cards connected by arrows. Each card has an input, an output, and a “測試一份文書” checkpoint before batch processing. A cost/quality explanation can be shown as an optional side panel, without making unsupported claims about specific models or prices.

### LLM Wiki and reuse

End with a clear boundary: only reviewed and accepted structured results move into the long-term research knowledge layer. A final diagram can show `原始文書 → AI 候選 → 人工確認 → 可重用資料`.

## Design guardrails

- Keep setup instructions secondary to the research decisions.
- Never show an AI answer without its source path.
- Distinguish `測試中`, `候選`, `已確認`, and `可重用` states.
- Avoid presenting a single workflow as the only valid method for all historical corpora.

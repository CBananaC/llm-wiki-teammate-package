試一試 手機版原型

裝置偵測：可以，不必只靠寬度。最可靠的純 CSS 寫法是 @media (pointer: coarse) and (hover: none)——判斷「主要輸入是手指、而且沒有滑鼠指標」， 這是手機／平板才會成立的組合，桌機把視窗縮窄並不會觸發。JS 端還有 navigator.userAgentData.mobile（Chromium 系）與 navigator.maxTouchPoints 可交叉驗證。

但兩種訊號都不完美：外接鍵盤與觸控板的 iPad 會回報 pointer: fine；觸控螢幕筆電則可能兩者皆有。 所以建議兩個條件取聯集：(pointer: coarse) and (hover: none), (max-width: 1040px)—— 真手機一定進手機版，桌機縮窄視窗也還是能看，不會卡住。

  • 整節剛好一個螢幕高（扣掉頂欄），進度列與對話框固定，只有視窗內部捲動。
  • 下載階段：PDF 直接放進「撰寫 Prompt」視窗裡，底部一條細長列放檔名與下載鈕，PDF 自動縮放到視窗大小。
  • 作答階段：視窗持續顯示 PDF（並跟著題目切換標示圖），不再逐句堆疊已答的 prompt。
  • 最後總覽時才把累積的 prompt 一次列出來，可複製。
